# Архитектура

```
core/                 симуляция (без графики)
  game.gd             Game: данные + состояние, apply_action(), порядок ходов
  data/game_data.gd   загрузка и проверка data/*.json
  hex/hex_grid.gd     гекс-сетка: odd-r, цилиндр, расстояния, линии, мировые координаты
  state/              GameState, GameMap (столбцы по клеткам), Player, Unit, City, GameRng
  map/map_generator.gd генератор карты
  rules/              правила: movement, pathfinder (A*), visibility (туман), yields,
                      city_rules (города), empire_rules (держава, исследования, конец хода),
                      district_rules (районы: размещение, соседство, уровни, Нерон),
                      city_life (санитария, порядок, эпидемии, губернаторы),
                      improvement_rules (строители)
  ai/ai_player.gd     ИИ: исследования, расселение, производство, строители, гарнизоны
data/                 весь контент и баланс (JSON)
view/                 отображение и ввод (Godot-узлы)
  main.gd/.tscn       точка входа, связывает ядро и отображение
  map/                MapView, построение мешей, шейдеры (туман через текстуру)
  map/improvement_meshes.gd — временные модели улучшений
  units_view.gd, cities_view.gd, overlay_view.gd, camera_rig.gd, hud.gd,
  map_style.gd (палитра, высоты)
tests/                тесты ядра (run_tests.gd + test_*.gd)
tools/                служебные скрипты: проверка скриптов, скриншоты, дымовой тест, автоигра
art/                  арты художника
docs/                 GDD.md (дизайн), STATUS.md (прогресс), этот файл
```

## Поток данных

```
ввод (view) ──action──▶ Game.apply_action ──▶ меняет GameState ──▶ [события]
                                                                   │
view ◀── читает GameState и события ◀──────────────────────────────┘
ИИ ──action──▶ тот же apply_action
```

## Карта

- Клетка — индекс `row * width + col`. Осевые координаты `(q, r)` для расчётов, `r == row`.
- Направления: 0=E, 1=NE, 2=NW, 3=W, 4=SW, 5=SE. Ребро `d` клетки соединяет её вершины `d` и `d+1`.
- Реки — битовая маска рёбер на каждой клетке, ставится симметрично (`GameMap.set_river_edge`).
- Рельеф: `RELIEF_FLAT/HILLS/MOUNTAIN`. Особенность, ресурс, улучшение — строковые id.

## Отображение карты

- Все основания тайлов на общей плоскости Y=0 (`MapStyle.tile_height`), без стенок между гексами. Высоту дают отдельные модели гор, холмов и растительности.
- Туман войны — текстура W×H (R: 0 не разведано, 0.5 разведано, 1 видно); у каждой вершины в UV2
  (у MultiMesh — в INSTANCE_CUSTOM) координаты её клетки. Неразведанное сплющивается в «пелену».
- Цилиндр: всё рисуется в трёх копиях со сдвигом на ширину карты; камера зациклена.
- Ландшафт — импортированные меши/текстуры в `art/`, загрузчик `view/map/landscape_models.gd`, пути и масштабы в `data/landscape_visuals.json`. Старые горные модели остаются в библиотеке, но не размещаются.

### Горные массивы

`MapGenerator` на новых картах размещает полные участки по контуру из
`data/game_setup.json:mountain_generation`, около прежних 7% суши с округлением
до целого массива. Участки только на суше, не пересекаются и не касаются друг
друга. В симуляции это обычные непроходимые горные клетки, без новых полей
сохранения. Ядро не загружает 3D-ресурсы; тест сверяет контур с моделью.

`view/map/mountain_massifs.gd` строит исключительно визуальный план по текущим
горным клеткам: сначала полные отпечатки исходной модели, затем связные остатки
до `mountain_massif.max_tiles` клеток. Одна группа — один экземпляр нового
GLB, без изменения симуляции или сохранений. Координаты группы разворачиваются
через шов цилиндра; одинаковая карта всегда получает одинаковое размещение.

`MapView` передаёт в MultiMesh номер группы, а в текстуре RG хранит 16-битный
номер группы, B — маску открытых рёбер. Шейдер `mountain_massif.gdshader`
ограничивает модель её клетками, адаптирует внешний склон и выбирает туман
по мировым X/Z каждого фрагмента, а не по одной опорной клетке всего массива.
Скрытые части не отрисовываются; открытая, но не видимая местность приглушается.
Полные совпадающие отпечатки сохраняют исходную геометрию модели.

Общий `landscape_pbr.gdshaderinc` сохраняет цвет, normal map и нужный канал
шероховатости glTF при подключении тумана. У массивов используется исходный
меш без готовых LOD, рассчитанных до деформации. У лесов и остальных моделей
LOD сохраняются. Визуальный план пересобирается только при изменении рельефа
или типов местности; обновление тумана идёт через общую текстуру.
